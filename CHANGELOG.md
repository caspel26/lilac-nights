# Changelog

## [1.1.0]

First release on the Visual Studio Marketplace, and the first with a light
theme.

- **Lilac Nights Light.** A second theme, generated from the dark one through
  `tools/variants/light.json` (`node tools/build-variants.mjs`), so both keep
  the same hue-per-job rules. Every syntax role is contrast-checked against the
  light background in CI.
- Java, C#, PHP, Vue and Markdown get their own scope rules instead of falling
  into generic ones: Java type references, primitives and annotations; C#
  built-in types and parameters; PHP types and attributes; Vue directives and
  interpolation; Markdown list markers, fence language, strikethrough, indented
  code and rules. Semantic rules for `delegate` and `annotationMember` cover
  the token types the C# and Java language servers emit.
- Readonly declarations no longer tie: `property.declaration.readonly`,
  `variable.classMember.declaration.readonly` and their `.definition` twins are
  explicit, the same class of fix as `variable.classMember.readonly` in 1.0.2.
- Comments move from `#8a7dad` to `#8b7eae` (4.49 to 4.55) so every syntax role
  clears WCAG AA, which the README had been claiming without it being true.
- Workbench state fixes: `terminal.ansiBrightBlue`, inactive selection
  backgrounds, input and dropdown borders, inactive activity bar icons, and tab
  hover and unfocused colors.
- New contrast gate (`.github/scripts/check-contrast.mjs`) in CI and in the
  release: per-role contrast, rank order and neighbour separation, for both
  themes.
- The `.vsix` no longer ships `CLAUDE.md`, `HANDOFF.md` or the design docs.
- The release workflow builds the tagged commit instead of the branch head,
  and is split into package, attach, Open VSX and Marketplace jobs so neither
  registry can strand the other. The Marketplace job publishes through OIDC
  Trusted Publishing and is gated by the `PUBLISH_MARKETPLACE` repository
  variable.
- Previews: a full workbench mock, a language gallery, new Java, C#, PHP and
  TSX previews, and light versions of all of them, all rendered from the theme
  files. The `render_preview.py` terminal mock now derives its file list from
  the manifest.
- README restructured: workbench and gallery above the fold in place of the
  collapsible badges, Marketplace badge and install option, a Light section,
  and an honest contrast claim. Per-language previews moved to
  `docs/previews.md` and "Making it yours" to `docs/customizing.md`.

## [1.0.6]

- HTML gets real, distinct coverage instead of riding on whatever generic
  scopes happened to apply: entities (`&amp;`, `&nbsp;`, ...) are now coral
  (`constant.character.entity`), and `<!DOCTYPE html>` is muted italic
  (`meta.tag.sgml.doctype`/`meta.tag.metadata.doctype`) so it reads as the
  boilerplate aside it is instead of competing with real markup.
- `render_preview.py` gains an HTML sample and preview, added to the README
  alongside the other languages. Its refinement pass now also gives tag
  punctuation (`<`, `>`, `/`) the same muted shade the theme itself uses for
  it, and attribute names render italic to match `entity.other.attribute-name`.
  The sample embeds a `<style>` and `<script>` block so the preview shows
  real CSS/JS tokenization (selectors, properties, hex colors, template
  literals) instead of reading as one flat wall of markup.

## [1.0.5]

- Go (and other statically-typed languages) read flatter than Python because
  every built-in primitive type (`string`, `int`, `bool`, `error`) shared the
  same honey as user-defined structs and interfaces — Go's mandatory explicit
  typing meant that one color did far more of the work than in Python.
  `type.defaultLibrary`/`class.defaultLibrary` are now a desaturated tan
  (`#c3a279`, italic), so built-in types read distinctly from your own types.
- `render_preview.py` never recognized `func` (Go) or `fn` (Rust) as starting
  a function signature — only `def`/`function` — so parameters (including Go
  method receivers) rendered in the default foreground instead of parameter
  pink. It also only colored a parameter at its declaration, not at any use
  inside the function body, unlike real semantic highlighting. Both are fixed;
  previews for every language are regenerated to match.

## [1.0.4]

No color changes — this release fixes the tooling and docs that had drifted
away from the theme:

- `render_preview.py` had two stale hardcodes despite its own docstring
  claiming it reads colors from the theme file: punctuation was pinned to the
  retired `#9a8fbd` instead of the current `#8a7dad`, and the terminal mock's
  colors (and the `.vsix` filename shown in it) were hand-typed rather than
  pulled from the theme and `package.json`. Both now resolve dynamically.
- `images/palette.png` was hand-made and had drifted out of sync with the
  theme (old azure, sage, red; missing the rose parameter swatch). It's now
  generated by `render_preview.py`, so it can't go stale again.
- README layout cleanup: the palette image wasn't wrapped in the same
  `<p align="center">` block as every other image in the doc; the Previews
  section carried a Python entry that duplicated the hero image already shown
  above the fold; the VS Code engine badge was still on the old azure hex.

## [1.0.3]

- Parameters retuned from `#fb92bb` to `#f17ec1`. Same hue-separation goals as
  1.0.2, refined twice more against real code:
  - Dimmed lightness/saturation (L .78/S .93 → L .72/S .80) so parameters no
    longer matched `self`'s brightness — they were competing for attention
    instead of `self` reading as senior, per the brightness-tracks-importance
    rule.
  - Nudged hue from 336.6° to 325°, closing the gap to `self` from 73° to
    61.5° while keeping a 20° buffer from orchid decorators — about as close
    as it can get without crowding them.

## [1.0.2]

- Parameters move from red (`#ff8a8e`) to rose (`#fb92bb`). The old red sat 95°
  from `self` in hue while being only 18° from numeric literals — too far from
  the token beside it, too close to the one below it.
- Functions lift to `#8ec5ff` and strings drop to `#8fdc98`, so the names you
  scan for outrank the string literals you don't.
- `variable.classMember.readonly` added, so a constant attribute like
  `settings.API_KEY` is colored by the theme instead of by whichever
  single-modifier rule happened to win the tie.

## [1.0.1]

- `self` and `cls` move from lilac to violet (`#b98cff`), so `self.attribute`
  reads as two distinct tokens instead of one flat color.
- Class fields stay white where they are *declared* and lilac where they are
  *used*, via `variable.classMember.declaration` and `property.declaration`.

## [1.0.0]

Initial release.

- Dark theme built on a lilac/violet spine (`#b98cff` → `#d7b8ff`) with seven
  supporting accents, each assigned exactly one job.
- Full semantic token support, including `variable.classMember` so Python
  attribute access (`session.external_session_id`) reads distinctly from plain
  variables.
- All syntax colors contrast-checked against the editor background at WCAG AA
  (≥4.5:1).
- Complete workbench coverage: symbol icons, inlay hints, ghost text, testing
  and debug views, notebooks, terminal ANSI, and diff/merge decorations.
- Extra grammar coverage for YAML, TOML, Dockerfile, shell, SQL, `.env`, CSS,
  and git commit messages.
